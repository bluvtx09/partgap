# PartGap v0.1 첫 결과: 부품 단위 보정치는 어디까지 옮겨지는가

2026-10-01. 질문과 판정 기준은 `PLAN.md`에 결과 전에 고정했다(수정 기록 포함).
숫자는 전부 `experiments/` 스크립트가 다시 만든다. 주 결과는 맞춤 절차 v2(`results/fits_v2/`, `results/analysis.json`)이고,
v1은 `results/analysis_v1.txt`에 남겨 두었다. v1과 v2의 결론은 같다.

## 결론 다섯 줄

1. **Phase 3 진입 조건은 통과했다.** 공개 원시 로그로 서보 6종(946개 로그)을 확보했다. 그중 STS3215는 연구실이 다른 두 개체가 있다.
2. **한 개체 안에서는 부하와 게인을 넘어 옮겨진다.** 가장 무거운 하중을 빼고 맞춰도 12개 중 11개가 1.5배 이내였고, 가장 높은 게인을 빼도 12개 모두 1.5배 이내였다.
3. **역구동(모터를 끄고 팔이 떨어지는 구간)은 옮겨지지 않는다.** 낙하 시험을 빼고 맞추면 12개 모두 불합격(1.8~16.8배)이었다. 구동 구간 오차는 그대로였고, 늘어난 오차는 거의 전부 토크가 꺼진 구간에서 나왔다.
4. **다른 개체로도 구동 거동은 옮겨지지만 역구동은 아니다.** 7.4V 개체의 마찰값을 12V 개체에 쓰고 모터 상수만 다시 맞추면, 구동 구간 0.5° vs 자기 맞춤 0.4°였다. 역구동 구간은 24° vs 5°였다. 사전 등록 판정(전체 오차)은 불합격이다.
5. **"DB 값 + 로그 2개 보정"으로도 메워지지 않았다.** 다섯 번 반복의 중앙값이 그 개체 전체 맞춤의 1.7배(M6), 2.2배(M1)였다(기준 1.5배). DB에서 출발한 쪽이 맨땅 출발보다 나은 것은 M6뿐이었다(1.86° vs 2.89°).

사업 가정 "한 번 재 두면 남의 개체에도 그대로 쓴다"는 **구동 중 위치 추종에 한해서만** 지지된다(개체 쌍 하나 기준).
충돌, 낙하, 토크 끔, 외력에 밀리는 상황처럼 역구동이 섞이면 지지되지 않는다.

## P0. 맞춤기 확인 — 통과

BAM 공개 파라미터와 같은 로그 전체에서 비교했다. 10쌍 모두 1.10배 기준 안에 들었다(v2: 0.69~1.03배).
8쌍은 공개값보다 오차가 작았다(XL330 M1은 0.998배로 사실상 같음). v1에서는 STS3215 7.4V M6가 1.12배로 불합격이었는데, v2(다른 맞춤 결과에서 출발해 다듬기)에서 1.03배가 됐다.

남은 수렴 문제: 분할 맞춤 4개가 v2 재맞춤 뒤에도 자기 학습 로그에서 전체 맞춤보다 5% 넘게 나빴다
(MX-64 M6 kp 1.09배, MX-64 M6 무작위 1.07배, STS3215 12V M1 무작위 1.43배, STS3215 12V M1 궤적 1.52배; `results/convergence_check.json`).
결론에 미치는 방향은 이렇다. MX-64 두 개는 Q1 비율을 약간 부풀리지만 둘 다 이미 합격이다. 12V M1 무작위는 Q2의 "자기 맞춤"을 약하게 만들어
이전이 실제보다 좋아 보이게 하므로, Q2 불합격 결론을 뒤집지 않는다. 12V M1 궤적은 Q1 궤적 비율을 부풀리지만, 궤적 분할은 수렴 문제가 없는 나머지 11개도 모두 불합격이다.

## Q1. 한 개체 안에서 조건 이전

비율 = (그 조건을 빼고 맞춘 모델의 오차) / (그 조건까지 보고 맞춘 모델의 오차), 같은 테스트 로그 기준. 1.5 이하면 합격.

| 빼고 맞춘 조건 | 합격 | 비율 범위 | 불합격 |
|---|---|---|---|
| 가장 무거운 하중 묶음 | 11/12 | 1.07~1.66 | STS3215 12V M6 (1.66) |
| 가장 높은 P게인 | 12/12 | 1.02~1.47 | 없음 |
| `lift_and_drop` 궤적 | 0/12 | 1.81~16.8 | 전부 |

**원인 (탐색 분석, 사전 등록 아님).** `lift_and_drop` 로그를 토크가 켜진 구간과 꺼진 구간으로 나눴다(`q1_mechanism`).
구동 구간은 빼고 맞춘 모델과 보고 맞춘 모델이 거의 같다(예: MX-64 M6 0.18° vs 0.17°, ST3025 M1 0.67° vs 0.60°).
토크가 꺼진 구간에서만 크게 벌어진다(MX-64 M6 7.2° vs 1.2°, STS3215 12V M1 35° vs 5.2°, ST3025 M1 22° vs 3.2°).
모터가 구동하는 동안에는 모터 쪽 토크가 마찰을 압도해서, 구동 로그만으로는 역구동 마찰(기어를 거꾸로 돌릴 때의 마찰)이 정해지지 않는다.
ST3025는 토크를 끈 `nothing` 궤적이 학습에 있는데도 실패했다. 그 로그는 팔이 거의 움직이지 않아서(최대 1.1°) 마찰을 알려 주지 못한다.

**스키마에 주는 뜻:** 하중과 게인은 측정 범위를 저장해 두고 범위 밖이면 경고하면 충분하다(범위 밖 증가폭 1.5배 이내).
역구동은 조건 축이 아니라 **반드시 측정해야 하는 시험 항목**이다. 낙하 시험이 없는 항목은 역구동 상황에서 쓰면 안 된다.

## Q2. 개체·연구실 이전 — 불합격

STS3215 7.4V(Rhoban)와 12V(T-K-233)는 감속비(345:1)와 기어 재질(구리)이 같고 모터 권선이 다르다
(데이터시트 정지 토크 19.5 / 30 kg·cm, 정지 전류 2.5 / 2.7 A). 맞춘 저항 2.5 / 4.1 Ω은 데이터시트의 V/I 3.0 / 4.4 Ω과 가깝다.

사전 등록 시험(12V 테스트 로그 19개):

| | M1 | M6 |
|---|---|---|
| (a) 12V 자기 맞춤 | 0.94° | 0.93° |
| (b) 7.4V 값 그대로 | 4.77° (5.1배) | 4.65° (5.0배) |
| (c) 7.4V 마찰 + 모터 상수만 12V로 맞춤 | 2.30° (2.5배) | 2.29° (2.5배) |
| (d) 보정 없음 | 12.3° | 12.3° |

판정 기준 "(b) 또는 (c) ≤ 1.5 x (a)"를 넘지 못했다. 보정 없음 대비로는 61~81% 줄었다.

**구간별 확인 (사후 분석, 12V 로그 97개 전체, M1):**

| | 구동 구간 | 역구동 구간 |
|---|---|---|
| 12V 자기 맞춤 (학습에 쓴 로그 포함, 낙관적) | 0.40° | 5.2° |
| 7.4V 마찰 + 모터 상수 재맞춤 | 0.51° | 24.2° |
| 7.4V 값 그대로 | 4.06° | 25.0° |

모터 상수를 맞춰 주면 구동 거동은 옮겨진다. 그대로 쓰면 구동 구간도 틀리는데, 모터 권선이 달라 토크 상수가 거의 두 배 차이이기 때문이다.
역구동은 옮겨지지 않는다. 12V 개체의 쿨롱 마찰은 BAM의 상한(0.2 N·m)에 붙었다. 7.4V 개체의 약 4배이고, 상한이 없었다면 더 컸을 수 있다.
같은 기어라도 출력축에서 본 마찰에는 모터 쪽 마찰이 감속비만큼 곱해져 들어오므로, "마찰은 기어박스 몫"이라는 가정 자체가 맞지 않을 수 있다.
개체 차이, 버전 차이(모터), 사용 이력 중 어느 것 때문인지는 이 한 쌍으로는 가를 수 없다.

## Q3. 온도 (탐색)

M6 전체 맞춤의 로그별 잔차와 첫 샘플 온도의 스피어만 상관: MX-64 0.19 (p 0.04), MX-106 0.02, XL330 0.24 (p < 0.001), ST3025 -0.35 (p < 0.001).
부호가 부품마다 다르고, 온도가 기록 순서·조건과 섞여 있다. 스키마에는 온도를 기록 칸으로만 두고 보정 축으로는 쓰지 않는다.

## Q4. MuJoCo 내보내기 — 통과

M1 항목을 MuJoCo 기본 위치 액추에이터 설정으로 바꿔 진자 로그 946개를 MuJoCo 3.14.0에서 다시 굴렸다.

| 부품 | BAM 시뮬 | MuJoCo 5 ms | 배율 | MuJoCo 1 ms |
|---|---|---|---|---|
| MX-64 | 1.41° | 1.54° | 1.09 | 1.54° |
| MX-106 | 1.02° | 1.15° | 1.12 | 1.13° |
| XL330 | 1.78° | 1.83° | 1.03 | 1.83° |
| STS3215 7.4V | 1.38° | 1.45° | 1.05 | 1.44° |
| STS3215 12V | 1.19° | 1.28° | 1.07 | 1.30° |
| ST3025 | 1.19° | 1.21° | 1.01 | 1.23° |

6종 모두 1.2배 기준 안에 들었다. 5 ms와 1 ms 차이는 0.02° 이하라 수치 오차는 무시할 수준이다(SimDiff식 자기 불일치 점검).
변환식: 게인 = error_gain x 게인비 x kp x Vin x kt / R, 힘 한계 = max_pwm x Vin x kt / R,
관절 감쇠 = 점성 마찰 + kt²/R(역기전력), frictionloss = 쿨롱 마찰.
BAM의 `to_mujoco`는 max_pwm을 힘 한계 대신 게인에 곱한다. 여기서는 토크 식과 정확히 같은 쪽을 썼다(`tests/test_export.py`).
펌웨어의 목표 속도 제한과 명령 지연은 MuJoCo에 대응 기능이 없어서 ctrl 앞단에서 처리한다(`partgap.export.CommandFilter`).

## Q5. DB + 로그 2개 보정 — 불합격

12V 개체에서 `lift_and_drop` 1개와 다른 궤적 1개를 무작위로 골라 맞추고, 나머지 95개 로그에서 평가했다(시드 5개).

| | M1 중앙값 | M6 중앙값 |
|---|---|---|
| (i) 7.4V DB 항목에서 출발 | 2.69° | 1.86° |
| (ii) 기본값에서 출발 | 2.18° | 2.89° |
| DB 항목 그대로 | 7.53° | 7.50° |
| 기준: 12V 전체 맞춤 | 1.20° | 1.12° |
| (i) / 기준 | **2.24배** | **1.66배** |
| (i)가 (ii)보다 나은 횟수 | 3/5 | 4/5 |

DB 값만 쓸 때보다는 크게 나아지지만(7.5° → 1.9~2.7°), 그 개체를 제대로 맞춘 수준(1.1~1.2°)에는 못 미친다.
로그 2개는 부족하다. 몇 개면 충분한지는 이번에 보지 않았다.

## Phase 3에 대한 판단

| 빌드맵 질문 | 답 |
|---|---|
| 공개 데이터로 부품 2~3종을 확보할 수 있나 (진입 조건) | 예. 6종 |
| 부품 단위 항목이 다른 조건에 쓸 만한가 | 하중·게인은 예. 역구동은 낙하 시험을 측정했을 때만 |
| 부품 단위 항목이 다른 개체에 쓸 만한가 | 구동 추종은 예(모터 상수를 맞출 때). 역구동은 아니오. 개체 쌍 하나뿐이라 시사 수준 |
| 짧은 보정으로 메울 수 있나 | 로그 2개로는 아니오 |

제안:
1. **PartGap v0.1은 무료 공개 자료와 조회 도구로 내놓는다.** MuJoCo 설정 변환이 검증됐고, 하중·게인 범위 경고와 역구동 경고를 정확히 줄 수 있다.
   simdiff-check 사용자에게 "부품을 시뮬에 넣는 법 + 남는 오차"를 알려 주는 부록 역할이다.
2. **사업의 중심에 두기 전에 개체 간 편차를 직접 잰다.** STS3215 7.4V를 3개 사서(개당 2~3만 원대), BAM 기록 스크립트로 Rhoban과 같은 진자 시험을 한다.
   같은 버전, 다른 개체의 역구동 마찰 편차가 7.4V↔12V 차이(4배)만큼 크면, DB는 "구동 추종 전용"이나 "개체별 측정 서비스"로 방향을 바꿔야 한다.
   이 측정은 Phase 4(저갭 관절 시제품)의 측정 장비와 겹친다.
3. 빌드맵의 Phase 3 종료 기준("외부 사용자 1팀이 써 보고 유용하다고 확인")은 공개 뒤에 사용자가 있어야 판정할 수 있다.

## 한계

- 시험대가 단일 진자뿐이다. 다관절 로봇에서 관절끼리 서로 미는 상황은 보지 않았다.
